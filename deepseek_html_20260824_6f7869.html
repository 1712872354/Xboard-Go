AI 辅助开发指导书 · 使用 Go 语言构建

📋 项目概述

本项目旨在开发一个功能完备的代理管理面板，类似 XBoard 或 V2Board。系统需支持用户管理、套餐订阅、节点管理、流量统计、支付集成等功能，并能够与代理节点（如 XrayR、sing-box）对接。

核心目标：构建一个高并发、模块化、可扩展的后端服务，前端后续可独立开发。

技术选型： Go 1.22+ PostgreSQL Gin + GORM Redis JWT

📆 开发里程碑（AI 任务分解）

  1. 阶段 1：基础框架搭建（第 1-2 周）

    • 初始化 Go 模块，引入 Gin、GORM、Redis、JWT、Zap 日志等依赖。
    • 配置管理（viper），加载环境变量、配置文件。
    • 实现基础中间件：CORS、请求日志、错误恢复、JWT 认证、RBAC 权限。
    • 数据库连接与自动迁移（GORM AutoMigrate）。
    • 健康检查接口 /healthz。

  2. 阶段 2：用户与认证模块（第 3-4 周）

    • 用户注册、登录、邮箱验证（可选，先实现基础注册登录）。
    • 密码加密（bcrypt），生成 JWT access token，refresh token。
    • 用户信息查询、修改密码、重置密码。
    • 管理员用户管理接口（列表、封禁、修改角色）。

  3. 阶段 3：套餐、订单与订阅（第 5-6 周）

    • 套餐 CRUD（管理员），用户可查看套餐列表。
    • 生成订单，模拟支付（先实现手动确认支付）。
    • 用户购买套餐后，更新用户流量额度、到期时间。
    • 生成订阅链接：/api/v1/client/subscribe?token=xxx，支持 Clash、V2Ray、Sing-box 格式。
    • 实现订阅内容生成逻辑，根据用户套餐中的节点组和节点类型动态生成配置。

  4. 阶段 4：节点管理与对接（第 7-8 周）

    • 节点 CRUD（管理员），支持添加 V2Ray/Xray 节点。
    • 实现节点 API（模拟 XrayR 对接）：
    • GET /api/v1/server/UniProxy/user：获取所有有效用户及节点关联信息。
    • POST /api/v1/server/UniProxy/push：节点上报流量使用情况。
    • POST /api/v1/server/UniProxy/alivelist：节点心跳/存活上报。
    • 节点测试连通性接口。

  5. 阶段 5：流量统计与扣减（第 9-10 周）

    • 接收节点上报的流量数据，写入 traffic_logs。
    • 更新用户 used_traffic，超出 traffic_limit 自动禁用。
    • 使用 Redis 原子操作或数据库事务防止并发超扣。
    • 提供用户流量查询接口（实时、历史）。

  6. 阶段 6：支付集成（第 11-12 周）

    • 接入支付宝/微信支付（沙箱环境）。
    • 实现支付回调处理，验证签名，更新订单状态并激活用户套餐。
    • 卡密兑换功能。

  7. 阶段 7：工单、审计与看板（可选）

    • 工单系统：用户提交工单，管理员回复。
    • 审计规则：设备数限制、IP 变更检测。
    • 管理员数据看板：收入统计、用户活跃度、节点状态。

🔒 安全注意事项

  • 所有用户输入必须进行校验和清理，使用 GORM 参数化查询防止 SQL 注入。
  • 密码使用 bcrypt（cost ≥ 10）存储，绝不明文。
  • JWT 设置合理过期时间（如 2 小时），并实现 refresh token 机制。
  • 订阅链接 token 需随机且可重置，支持绑定 IP 或设备数限制。
  • 支付回调必须验证签名，防止伪造回调，订单状态更新需幂等。
  • 节点上报流量接口需要 API 密钥认证，避免伪造流量数据。
  • 管理接口（/admin/*）需严格 RBAC 权限校验。
  • 使用 Redis 实现登录、订阅等接口的限流，防止暴力破解。
  • 日志中不得记录密码、token 等敏感信息。

🚢 部署建议

  • 使用 Docker 容器化部署后端、PostgreSQL、Redis。
  • 前端构建为静态文件，由 Nginx 托管，反向代理 /api 到后端。
  • 节点使用 XrayR 或自研 agent，配置对接面板 API。
  • 生产环境开启 HTTPS，配置域名。
  • 定期备份 PostgreSQL 数据库，监控 Redis 内存使用。
