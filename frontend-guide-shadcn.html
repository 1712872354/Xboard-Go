🚀 项目初始化步骤

  1. 创建 Vite + React + TS 项目：pnpm create vite frontend --template react-ts
  2. 安装 Tailwind CSS：按照官方文档（Vite 指南）配置。
  3. 初始化 shadcn/ui：npx shadcn-ui@latest init，选择默认配置。
  4. 添加所需组件：例如 npx shadcn-ui@latest add button card input table dialog dropdown-menu tabs form 等。
  5. 安装其他依赖：pnpm add react-router-dom @tanstack/react-query zustand axios react-hook-form zod @hookform/resolvers
  6. 设置路径别名（可选）：在 tsconfig.json 和 vite.config.ts 中配置 @/ 指向 src/。

🔌 与后端 API 对接

Axios 实例配置

// src/lib/axios.ts
import axios from 'axios';
import { useAuthStore } from '@/store/auth';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api/v1',
  timeout: 10000,
});

api.interceptors.request.use((config) => {
  const token = useAuthStore.getState().accessToken;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;
      try {
        const newToken = await refreshAccessToken();
        useAuthStore.getState().setAccessToken(newToken);
        originalRequest.headers.Authorization = `Bearer ${newToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        useAuthStore.getState().logout();
        window.location.href = '/login';
      }
    }
    return Promise.reject(error);
  }
);
export default api;

React Query 使用示例

// src/hooks/useUsers.ts
import { useQuery } from '@tanstack/react-query';
import api from '@/lib/axios';

export function useUsers(page: number) {
  return useQuery({
    queryKey: ['users', page],
    queryFn: async () => {
      const { data } = await api.get('/admin/users', { params: { page } });
      return data;
    },
    keepPreviousData: true,
  });
}

认证状态管理（Zustand）

// src/store/auth.ts
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

interface AuthState {
  accessToken: string | null;
  refreshToken: string | null;
  user: User | null;
  setTokens: (access: string, refresh: string) => void;
  setUser: (user: User) => void;
  logout: () => void;
}

export const useAuthStore = create<AuthState>()(
  persist(
    (set) => ({
      accessToken: null,
      refreshToken: null,
      user: null,
      setTokens: (access, refresh) => set({ accessToken: access, refreshToken: refresh }),
      setUser: (user) => set({ user }),
      logout: () => set({ accessToken: null, refreshToken: null, user: null }),
    }),
    { name: 'auth-storage' }
  )
);

📄 关键页面实现要点

登录页

  • 使用 react-hook-form + zod 校验邮箱和密码。
  • 调用 POST /auth/login，成功后存储 token 和用户信息，跳转仪表盘。
  • 错误提示使用 shadcn/ui 的 Alert 或 Toast。

用户仪表盘

  • 使用 Card 组件展示流量使用情况（进度条、环形图）。
  • 获取 GET /user/profile 获取用户信息。
  • 可集成 Recharts 显示近 7 天流量趋势（需要后端提供相应 API）。

套餐购买流程

  1. 展示套餐卡片列表，点击“购买”弹出确认对话框（Dialog）。
  2. 调用 POST /orders 创建订单，返回订单号和支付链接/二维码。
  3. 根据支付方式（支付宝/微信/卡密）显示不同支付界面。
  4. 轮询订单状态或等待支付回调后刷新用户信息。

节点管理（管理员）

  • 使用 Table 展示节点列表，支持分页、搜索、排序。
  • 添加/编辑节点使用 Dialog + Form，字段包括类型、地址、端口、倍率等。
  • 测试连通性按钮调用 POST /admin/nodes/test，显示结果。

订阅页面

  • 展示订阅链接（只读输入框 + 复制按钮），提供重置 token 按钮。
  • 下载配置文件按钮：直接链接到后端 /api/v1/client/subscribe?token=xxx，由后端生成文件并下载。
  • 使用 Tabs 切换不同格式（Clash、V2Ray、Sing-box）的预览。

🧩 推荐的 shadcn/ui 组件

  • 布局： Sheet（移动端侧边栏）、Sidebar（可自定义）
  • 导航： NavigationMenu、Tabs、Breadcrumb
  • 数据展示： Table、Card、Badge、Avatar、Progress
  • 表单： Form、Input、Select、Checkbox、DatePicker、Switch
  • 反馈： Dialog、AlertDialog、Toast（sonner）、Tooltip
  • 其他： DropdownMenu、Command（搜索）、ScrollArea、Skeleton（加载占位）

按需添加组件，避免一次性引入过多，保持打包体积可控。

🔄 状态管理与数据流建议

  • 服务端状态（用户列表、节点、订单等）：统一使用 TanStack Query，不要手动存入全局状态。
  • 客户端状态（认证信息、主题、UI 偏好）：使用 Zustand，轻量且易用。
  • 表单状态：使用 react-hook-form 的局部状态，避免全局污染。
  • 对于需要实时更新的数据（如节点状态），可设置 refetchInterval 或使用 WebSocket（后续扩展）。

🔒 前端安全注意事项

  • 不在前端存储敏感信息（密码、支付密钥），token 存储在内存或安全 cookie 中（HttpOnly 更佳）。
  • 所有 API 请求使用 HTTPS，生产环境禁止明文传输。
  • 对用户输入进行前端校验（Zod），但后端仍需二次校验。
  • 避免 XSS：React 默认转义，但使用 dangerouslySetInnerHTML 时需谨慎。
  • 使用 Content Security Policy（CSP）限制资源加载。
  • 处理 401 时自动刷新 token，避免频繁登录。
  • 路由守卫必须同时在前端和后端实现，前端仅提升体验。

📆 前端开发里程碑

  3. 第 3 周：开发用户仪表盘、套餐列表与购买流程、订阅管理页面。
  4. 第 4 周：开发管理员页面：用户管理、节点管理、套餐管理、订单管理（基于表格和表单）。
  5. 第 5 周：数据看板（图表集成）、工单系统、卡密兑换。
  6. 第 6 周：整体 UI 优化、响应式适配、错误处理、加载状态、空状态、测试与部署准备。

🚢 部署建议

  • 使用 pnpm build 生成静态文件，部署到 Nginx 或静态托管服务（Vercel、Netlify、Cloudflare Pages）。
  • Nginx 配置反向代理 /api 到后端服务，避免跨域问题。
  • 配置 VITE_API_BASE_URL 环境变量，区分开发和生产环境。
  • 使用 CI/CD（GitHub Actions）自动化构建和部署。
  • 开启 gzip 压缩，优化加载速度。
